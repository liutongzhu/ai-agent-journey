# Engineering Principles — 工程与安全原则

> 本项目的红线。任何关卡的设计与实现都不得违背；代码评审与 Boss 战以此为标尺。

## 输入与校验

1. **模型输出属于不可信输入**——像对待用户输入一样对待 LLM 生成的每一字节。
2. **ToolCall 必须严格校验**——解析失败、字段缺失、类型不符一律拒绝。
3. **Tool Registry 采用白名单**——只有显式注册的工具可被调用，没有隐式发现。
4. **参数必须符合 Schema**——多余参数、缺参数、类型错误都不放行。
5. **不使用 `shell=True`**——参数列表化传递，杜绝注入面。

## 执行与隔离

6. **不直接执行模型生成的任意 Shell 字符串**——可执行命令必须来自白名单或模板。
7. **文件操作必须有明确工作区边界**——resolve 之后仍落在工作区内才放行。
8. **Sandbox 启动失败必须 Fail Closed**——隔离建不起来就拒绝执行，绝不退化到无隔离运行。
9. **工具执行需要超时、取消和资源清理**——任何执行都有上限，任何子进程都要有人收尸。
10. **不能把简单路径校验当作完整隔离**——路径校验是约束，Namespace/Sandbox 才是隔离，宣传与实现要诚实。

## 状态与恢复

11. **Checkpoint 恢复需要考虑幂等性**——恢复 ≠ 重放，副作用步骤要能识别自己做过什么。
12. **未知结果的有副作用操作不能盲目重试**——「可能已经做了」比「确定没做」更危险。
13. **Workflow 必须有停止条件**——循环守卫、最大重试、熔断，没有终点的工作流是事故。

## 编排与调度

14. **Task Scheduler 必须有明确调度策略**——FIFO 或其他，写清楚；没有策略的调度是竞争。
15. **权限审批与执行隔离是不同机制**——审批管「应不应该」，隔离管「伤不伤得到」，互不替代。

## 生态与信任

16. **MCP 工具也属于外部信任边界**——外部工具默认不可信：校验、限权、超时一样不能少。

## 可观测与诚实

17. **结构化 Trace 应贯穿执行过程**——能回答「刚才发生了什么」的系统才可调试。
18. **区分工具执行成功与任务完成成功**——退出码 0 只是执行成功，目标达成才是任务成功。
19. **不泄露 API Key、Token 和敏感数据**——凭据只走环境变量，日志与 Trace 脱敏。
20. **不虚构测试结果或性能指标**——每个数字都能复现；演示成功不等于系统可靠。

## 使用方式

- 每关任务书的 Victory Conditions 都映射到本清单的子集。
- Boss 战失败 = 某条原则被击穿，修复后需在 Learning Notes 中说明是哪一条。
