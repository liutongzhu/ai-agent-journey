## 核心问题

为什么一次 Tool Calling 还不能让 Agent 自主完成复杂任务?

因为「修好这个 bug」从来不是一步:读代码 → 定位 → 修改 → 跑测试 → 失败 → 再改 → 再测。一次调用是「一令一动」,自主执行需要「决策 → 行动 → 观察 → 再决策」的循环,直到完成或触发停止条件。

## 核心比喻:开车导航(全新比喻,不复用马车)

导航从来不一次算完美全程:**规划 → 开一段 → 重新定位 → 再规划**,直到到达。

故事线(正文展开):老司机为什么敢开进陌生城市?不是因为他背下了全城地图,而是因为他信任「走-看-调」这个循环本身。堵车了就重算,环岛绕不出来就靠边停车——循环的正确性不靠每步完美,靠的是持续修正 + 知道何时该停。

## 概念映射表

| 比喻 | 技术 |
|---|---|
| 目的地 | 任务目标 |
| 规划下一段路 | 模型决策(生成 ToolCall 或最终回答) |
| 开一段路 | 工具执行 |
| 重新定位 | 工具结果回填(Observation) |
| 堵车重算 | 中途意外,模型调整计划 |
| 到达 | 输出最终回答,任务完成 |
| 最多绕 N 圈 | 步数预算(Token / Step Budget)与停止条件 |

## 真实的技术原理(TODO:正文时绘制 Mermaid 原理图;叙事插画单独制作)

Agent Loop:

```text
模型决策 → 工具执行 → 结果回填 → 模型再决策 → ……
  ↓ 停止条件
最终回答 / 达到最大轮数 / 上下文预算耗尽 / API 失败
```

两种模式:确定性 Mock(行为可预测,便于测试)与真实 LLM API(可体验自主工具调用)。

## 比喻的局限

- 导航的「再规划」是固定算法;模型的再决策是生成式的,行为不保证一致。
- 导航从不遗忘路线;Agent 的上下文有限,记忆需要主动管理(后续关卡展开)。
- 导航没有权限概念;真实 Agent 每一步工具调用都要过校验与授权。
